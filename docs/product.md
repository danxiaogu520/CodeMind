# 产品与范围

## 1. 产品目标

CodeMind 帮助开发者在不了解代码库的情况下，快速获得有来源依据的项目级答案，并完成需要多步检索和分析的任务。

核心成功标准不是回答“像是正确”，而是：

- 结论可追溯到具体仓库版本、文件和代码行；
- 检索结果能覆盖实现、入口、调用方和相关配置；
- 仓库变化后可以增量更新，不依赖全量重建；
- 分析过程可观察、可取消、可重试；
- 模型、向量库和 Agent 框架可以替换。

## 2. 目标用户与场景

### 目标用户

- 新加入项目、需要快速熟悉代码的工程师；
- 维护陌生遗留系统的开发者；
- 进行代码审查、影响面分析和技术调研的研发人员；
- 希望接入 IDE/LSP 的 AI 开发工具开发者。

### MVP 用户故事

1. 用户导入本地目录或 Git URL，并看到索引进度与错误文件。
2. 用户询问“认证入口在哪里”，得到带文件、符号和行号引用的回答。
3. 用户询问“`login` 被谁调用”，得到一层静态调用关系和不确定性说明。
4. 用户询问“解释 `auth` 模块”，Agent 汇总目录职责、核心符号、依赖和主流程。
5. 用户重新导入新 commit，只更新发生变化的文件和索引记录。

## 3. MVP 范围

### 包含

- 单仓库、单默认分支；
- Python、Rust、JavaScript、TypeScript；
- 公开 Git URL 和服务端允许目录内的本地路径；
- 文件/符号级结构化切分；
- Vector + BM25 + RRF 融合 + 可选 Cross-Encoder Rerank；
- 文件结构、符号定义、粗粒度 import/call 关系；
- 普通问答与 `explain_module`、`trace_symbol` 两类工作流；
- 项目摘要、分析结果和会话工作记忆；
- REST API、Docker Compose、结构化日志、阶段耗时和 Run usage；可抓取指标与告警留待生产化阶段。

### 明确不包含

- 自动修改或提交代码；
- 私有 Git 凭证托管与多租户权限系统；
- 编译器级精确跨语言调用图；
- 实时协同编辑、完整 Web IDE；
- GPU 模型训练；
- 全自动执行任意仓库脚本。

这些限制用于保护 MVP 的交付质量，并不阻断后续扩展。

## 4. 非功能需求

| 维度 | MVP 目标 |
|---|---|
| 可追溯性 | 每条代码事实包含 `repository_id + commit_sha + path + line_range` |
| 增量性 | 未变化文件不重新解析与 Embedding |
| 性能 | 10 万 Chunk 项目 P95 检索小于 2 秒，不含生成 |
| 可用性 | 单文件解析失败不导致整个索引任务失败 |
| 安全性 | 不执行被索引仓库代码；路径经过根目录约束与规范化 |
| 可替换性 | LLM、Embedding、Reranker、Vector Store 均通过端口接口接入 |
| 可观察性 | 每个请求和 Agent Run 有 trace id、阶段耗时与 Token/模型成本 |

## 5. 产品指标

- Retrieval Recall@10：人工标注集达到 0.80；
- 引用有效率：回答中的引用可定位且支持结论，达到 0.90；
- 增量索引命中率：仅修改少量文件时，跳过率达到 0.95；
- Agent 任务完成率：基准任务集达到 0.80；
- 无依据回答率：低于 0.05。
