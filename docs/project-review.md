# 项目审查与改进建议

本页记录 2026-07-21 对 CodeMind `0.1.0` 工作区的全景审查，作为“当前事实、近期改进和后续路线”的入口。历史阶段验收仍以[实施路线图](roadmap.md)和各阶段报告为准。

## 结论

CodeMind 已经形成结构完整、边界清楚、可演示的单机 MVP：摄取、解析、版本化索引、混合检索、可恢复 Agent、分层 Memory、API/CLI/Web Demo 和 Compose 发布栈均有对应实现。领域层和应用层保持框架无关，测试覆盖主要正常路径与关键安全边界，适合继续迭代，不建议重写。

当前最重要的工作不是继续增加 Agent 工作流，而是把“作品级发布”推进到“可安全运营的服务”：补认证与资源治理、任务租约、指标告警、数据生命周期和真实模型 Provider，再基于稳定基线开发 Git 历史、影响面分析和 IDE 集成。

## 做得好的地方

- `domain → application → infrastructure/interfaces` 的依赖方向由工具强制，而不只存在于架构图中；
- 索引版本先构建后激活，Run 绑定单一版本，避免查询读取半成品；
- Dense、BM25、Symbol 和 Reranker 均允许局部降级，回答引用受当前 Evidence 白名单约束；
- 原生 Parser 进程隔离、路径规范化、Git 凭证拒绝、SSRF 检查和只读容器形成了有效的 MVP 安全基础；
- 增量索引、Memory 失效、SSE 续传和 crash-resume 都有实现与测试证据，而不是仅有设计文档；
- 离线 Provider 和小型 fixture 让开发与 CI 可重复运行。

## 需要修复或完善

### P0：保持主分支可发布

1. **质量门禁必须始终全绿。** 本次已修复 4 个文件的 Ruff 格式漂移。建议在开发机使用 pre-commit 或等价的提交前命令，避免只在 CI 暴露格式问题。
2. **文档必须区分“已实现”和“目标”。** 本次已修正健康检查状态、部署安全能力和 Backlog 漂移；以后 API、配置或运行行为变更应与代码同一变更提交。

### P1：对外部署前完成

1. **API 访问与资源治理。** 当前没有认证/授权、租户隔离、全局限流、请求体上限、仓库总大小/文件数上限或并发 Run/Job 配额。现状适合本机和可信内网演示，不应直接暴露到公网。
2. **索引任务租约。** 已有原子领取、陈旧任务回收和最大尝试次数，但长时间 clone、Embedding 或索引写入期间缺少独立心跳；接入远程 Provider 后，固定超时可能将仍在执行的任务误判为陈旧。需要租约续期、幂等提交和索引任务取消。
3. **可观察性。** 已有结构化日志、trace id、阶段耗时和 Run usage，但没有可抓取的 metrics、队列深度、告警规则和跨 API/Worker 的 trace 传播。部署文档中的指标目前是目标清单。
4. **数据生命周期。** 旧索引版本可回收，但仓库删除、向量/BM25/Memory 级联清理、审计记录、备份编排和恢复演练尚未产品化。
5. **生产 Provider。** 已提供零 API 费用的 Ollama Qwen3 Embedding/LLM 适配器、模型版本隔离、超时和模板回退；Reranker 仍是启发式实现。下一步需要用扩大后的冻结评测集决定是否启用模型 Reranker，并继续完善重试、并发和资源指标。
6. **敏感内容检测。** 当前只跳过私钥头和 AWS Access Key 形态；需要可配置规则、误报处置、扫描统计，并明确远程模型调用前的数据边界。

### P2：提升工程效率与产品完整性

1. 补公开的 Tree/Symbol/Relation 分页 API；Agent 内部已有相应只读工具，但外部 API 契约还不完整。
2. CI 增加覆盖率下限、空库迁移与模型漂移检查、容器 smoke test、依赖漏洞扫描和镜像/SBOM 检查；第三方 Action 与基础镜像建议固定到 digest 或提交 SHA。
3. 扩大评测集规模和难度，加入同名符号、大仓库、生成代码、语法错误、重命名/删除、Provider 超时和检索全路失败场景；当前小 fixture 的满分不能代表真实仓库质量。
4. 为 SQLite BM25 多进程单写多读和 PostgreSQL/Qdrant 容量建立压测拐点，达到阈值后再决定独立检索服务或分布式队列，避免过早拆分模块化单体。
5. API 补仓库列表、任务列表/取消、分页与管理接口；Demo UI 增加失败恢复、索引警告和降级状态展示。

## 建议执行顺序

```text
发布卫生与文档准确性
        ↓
认证/配额 + 任务租约 + 指标告警 + 数据清理
        ↓
真实模型 Provider + 大规模回归评测
        ↓
Git 历史/影响面分析/IDE 集成
        ↓
多租户与分布式扩展（有容量证据后）
```

具体版本阶段、验收标准见[实施路线图](roadmap.md)，可领取任务见[工程 Backlog](backlog.md)。
